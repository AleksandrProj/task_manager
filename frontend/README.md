# Task Manager — frontend

Клиентская часть на React, JavaScript и Vite. Маршруты настроены через React Router,
стили — CSS Modules. Приложение использует Django REST API.

## Текущий этап

Готова основа приложения: маршруты, начальный макет, общий API-клиент и прокси
для Django. Добавлены общие компоненты: кнопки, поля, карточки, сообщения,
статусы и состояния загрузки. Полностью работает страница входа: JWT, выход,
восстановление сессии и защита страниц. Готов список задач: данные загружаются
с API, статусы, приоритеты и исполнители отображаются на компьютерах и телефонах,
есть пагинация, загрузка, ошибка и пустой список. Также готова форма создания:
она проверяет название, позволяет выбрать статус, приоритет и исполнителя,
показывает ошибки API и возвращает к списку после сохранения. Доступна страница
подробностей задачи с её статусом, приоритетом, участниками и датами; из списка
создатель может удалить задачу после подтверждения. На странице задачи доступны
список комментариев с пагинацией, добавление нового комментария и удаление
своих комментариев после подтверждения. Создатель также видит переход к
редактированию задачи. Страница редактирования загружает текущие данные: создатель
сохраняет все поля задачи, а исполнитель может изменить только статус через
отдельный API-маршрут. Изменение комментариев реализуется следующей отдельной
задачей.

Пагинацией задач и комментариев управляет Django REST API. Клиент не задаёт
размер страницы и не рассчитывает её номер: для переходов и номеров страниц он
использует ссылки `next`, `previous` и `pages` из ответа API.

## Запуск

Нужны Node.js 24+ и npm. Версия для nvm указана в `.nvmrc`.
Сначала запустите backend по [его инструкции](../backend/README.md).
Затем из корня проекта:

```sh
cd frontend
npm ci
npm run dev
```

Откройте <http://127.0.0.1:5173>. Если порт занят, сервер сообщит об этом,
не переключаясь на другой порт автоматически. Остановить его можно через Ctrl+C.

По умолчанию Django ожидается на `http://127.0.0.1:8000`.
Если backend работает по другому адресу, создайте `.env` из `.env.example`:

```sh
cp .env.example .env
```

Укажите в нём `BACKEND_URL`, например `http://127.0.0.1:8001`, и перезапустите Vite.
Эта переменная используется только сервером разработки и предпросмотра.
Секрет Django и пароль БД во frontend не нужны.

Браузер отправляет запросы на `/api/` по адресу frontend. Vite перенаправляет их
в Django, поэтому отдельная настройка CORS для этого варианта запуска не нужна.
Ответ `401` от защищённого API без JWT — ожидаемое поведение.

Для открытия с телефона в той же локальной сети:

```sh
npm run dev -- --host 0.0.0.0
```

На телефоне используйте `http://<локальный-IP-компьютера>:5173`.
Запросы `/api/` продолжат идти через Vite к backend на компьютере.

## Маршруты

| Адрес             | Страница                  |
| ----------------- | ------------------------- |
| `/login`          | Вход                      |
| `/tasks`          | Доступные задачи          |
| `/tasks/new`      | Создание задачи           |
| `/tasks/:id`      | Подробности и комментарии |
| `/tasks/:id/edit` | Редактирование задачи     |

Корневой адрес `/` перенаправляет на `/tasks`. Для неизвестного адреса есть
страница «Страница не найдена». Все маршруты `/tasks` требуют входа. После
авторизации пользователь возвращается на запрошенную страницу. Если пользователь
уже вошёл, `/login` перенаправляет на список задач.

## Авторизация

Используйте имя пользователя и пароль существующей учётной записи Django.
Пользователей создаёт администратор; самостоятельной регистрации и восстановления
пароля в текущем API нет. Для создания администратора смотрите инструкцию backend.

Форма проверяет обязательные поля, позволяет показать пароль, сообщает об ошибках
и блокирует повторную отправку во время входа. Поддерживаются автозаполнение,
клавиатура и мобильные экраны.

При входе клиент получает JWT через `POST /api/auth/token/`, затем загружает
профиль через `GET /api/users/me/`. Access хранится только в памяти, refresh —
в `sessionStorage` текущей вкладки. Пароль не сохраняется. После перезагрузки
страницы refresh позволяет получить новый access и восстановить профиль.

При ответе `401` клиент обновляет access через `POST /api/auth/token/refresh/`
и повторяет запрос один раз. Одновременные запросы используют одно обновление.
Недействительный refresh завершает сессию; при временной ошибке соединения
на экране восстановления можно повторить попытку.

Кнопка «Выйти» удаляет токены из браузера. Серверного отзыва токенов API пока
не предоставляет: ранее выданные токены действуют до истечения своего срока.

## Работа с API

Для защищённых запросов используйте `auth.request`: он добавляет JWT и обновляет
access при необходимости. Путь передаётся с начальным `/`, без префикса `/api`.

```js
import { auth } from './auth/auth.js'

const tasks = await auth.request('/tasks/?page=1')

await auth.request('/tasks/', {
  method: 'POST',
  data: { title: 'Новая задача' },
})
```

Клиент передаёт JSON и Bearer-токен, возвращает данные ответа либо `null` для 204.
При ошибке выбрасывается `ApiError`: `status` содержит HTTP-код, `details` —
ошибки полей или подробности ответа. При отсутствии соединения `status` равен 0.
Параметр `signal` позволяет отменить запрос через `AbortController`.

Сессионные cookies не отправляются. Низкоуровневый `apiRequest` находится
в `src/api/client.js` и используется внутри авторизации. Состояние входа
в React доступно через `useAuth()` из `src/auth/useAuth.js`.

## Общие компоненты интерфейса

Компоненты находятся в `src/components/ui/`. Общие цвета и размеры задаются
CSS-переменными в `src/index.css`, стили компонентов — в `ui.module.css`.

| Компонент                    | Назначение                                                           |
| ---------------------------- | -------------------------------------------------------------------- |
| `Button`, `ButtonLink`       | Кнопки действий и ссылки, оформленные как кнопки                     |
| `FormField`                  | Поле ввода, `textarea` или `select` с подписью, подсказкой и ошибкой |
| `Card`, `PageHeader`         | Карточка содержимого и заголовок страницы с действиями               |
| `Alert`                      | Ошибка, успешное действие или информационное сообщение               |
| `Badge`                      | Текстовая метка статуса или приоритета                               |
| `EmptyState`, `LoadingState` | Пустой список и загрузка                                             |

У `Button` по умолчанию `type="button"`: для отправки формы укажите `type="submit"`.
Параметр `loading` блокирует повторное нажатие и показывает текст `loadingText`.
`ButtonLink` сохраняет поведение обычной ссылки и используется для переходов.

`FormField` создаёт уникальный ID и связывает поле с подписью, подсказкой и ошибкой.
Для многострочного текста передайте `as="textarea"`, для списка — `as="select"`
с дочерними `option`. Поддерживаются стандартные свойства полей, включая
`name`, `required`, `disabled`, `value` и `onChange`.

При запущенном `npm run dev` примеры доступны на
[странице компонентов](http://127.0.0.1:5173/ui). Там можно проверить ошибки формы,
состояния кнопок и мобильную вёрстку. Данные примера не отправляются в API.
Маршрут `/ui` и страница примеров исключены из итоговой сборки.

## Проверки и сборка

Команды выполняются из `frontend`:

```sh
npm run lint
npm run format:check
npm test
npm run build
```

`npm test` проверяет API-клиент и авторизацию: вход, восстановление сессии,
обновление JWT, одновременные запросы, выход, ошибки и отмену запросов.
Для автоматического форматирования используйте `npm run format`.

Сборка создаётся в `dist/`. Для её локального просмотра:

```sh
npm run preview
```

Адрес предпросмотра — <http://127.0.0.1:4173>. Прокси к Django работает и здесь.
Для общего запуска собранного приложения понадобится отдельно настроить раздачу
frontend, перенаправление `/api/` в Django и возврат `index.html` для маршрутов
интерфейса. Vite preview предназначен для локальной проверки сборки.

